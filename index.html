01 · Overview

Executive Summary

Triply is materially further along than a typical MVP-stage project. The core, non-negotiable feature — a hallucination-free AI itinerary generator — is live and verified end-to-end against the real Gemini API. Since the audit snapshot, CI/CD + Render landed and the data-ownership story was consolidated; the remaining risk is still concentrated in data provisioning and a handful of contract-enforcement shortcuts, not in unbuilt architecture.

What's genuinely working

Authentication, trip CRUD, destination-first planning, AI itinerary generation (live Gemini E2E), 0%-invented-place grounding (prompt + validation + DB-FK), cost aggregation, and partial regeneration all have real evidence. Since the audit: a gated CI/CD pipeline (backend tests on a real SQL Server container + Flutter suite + Render deploy hook), budget-currency conversion for suggestions, and a round of mobile session/profile fixes have all merged.

What's blocking, and why it matters

Fresh environments still cannot run the core feature — and it got sharper: PR #66 removed the backend's static seed on purpose, so a fresh database starts with zero reference rows and the AI-track Python seeders are the only provisioning path. Nothing runs them automatically, and mobile QA is additionally blocked on a real GEMINI_API_KEY.

What's simply not built

Flutter Web (FR-WEB-001, a Must-have) is still an empty Frontend/ directory — and its first QA blocker is already on record (CORS: the backend allows only localhost:5173 by default). UI/UX and Cybersecurity ownership remain unresolved (TBD since the Team & Responsibilities doc). Hosting, however, has moved: a Render blueprint now exists.

What's documented but drifted from reality

The 2026-09-19 QA log reported backend CI red; the CI/CD pipeline has since landed, but its latest status wasn't re-verifiable locally — check the newest runs before trusting main. Docs still lag: 20 tables shipped vs. 17 documented, .NET 9 shipped vs. .NET 8 specified.

02 · Product

What The Project Is

Reconstructed from the Master Plan and SRS — the single source of truth for scope.

Problem & value

Manual trip research is slow and generic. Triply turns a destination or a budget into a personalized, day-by-day itinerary with a transparent, category-level cost estimate — without requiring travel-agency expertise.

Users

Individuals and families planning domestic or international trips. Two entry paths: destination-first (I know where) and budget-first (suggest where, within my budget).

Core workflow

Register/login → preferences (destination or budget + interests) → AI-generated itinerary → category cost breakdown → view / edit / regenerate part of the plan → save → return later.

Platforms & stack

Flutter (mobile + Web, one codebase) · ASP.NET Core Web API (modular monolith) · SQL Server via EF Core · Gemini API for generation, backend-owned integration.

Explicitly out of scope

Flight booking, hotel booking, in-app payments, social/reviews, loyalty programs, a travel marketplace, real-time flight tracking, live/verified pricing feeds — none justified by a stated requirement or current team capability.

The project's one non-negotiable rule

0% of places/activities in a generated itinerary may be outside the internal curated dataset. Every other design decision in the system — the database's non-nullable foreign key, the two-layer validation pipeline, the prompt design — exists in service of this one rule.

04 · Flow

End-to-End AI Generation Flow

The system's central loop, reconstructed from AiOrchestrationService.cs and verified live during this audit (real Gemini call, Paris itinerary, correct cost breakdown).

  1. Client requests generation — POST /api/trips/{id}/generate, JWT + ownership-checked.
  2. Dataset loaded — active Places (+ Destinations for budget-first) fetched from SQL Server as grounding context. Fails hard today on a fresh database — see Slide 9.
  3. Prompt built — grounding place list (names only, no prices/IDs) + exact per-day dates, handed to Gemini with a structured JSON schema.
  4. Gemini called — structured output enforced via responseJsonSchema; response parsed into a typed DTO.
  5. Validated — every place/destination name resolved against the database, 0% tolerance; category and day-structure rules checked.
  6. Persisted — on success, itinerary + cost breakdown written in one transaction; trip status → GENERATED. On failure, bounded retry (3 attempts), then a clear 422 error — never a fabricated plan.

Journeys explicitly covered by the SRS

Covered end-to-end

New registration → login; destination-first planning; budget-first suggestion (code path); partial day/item regeneration; save and retrieve a trip.

Covered by design, gap in enforcement

"AI generation fails → clear error, not a broken state" ✅ built. "Requested destination isn't supported → inform, don't fabricate" — validator does not currently filter by IsSupported (Slide 12).

08 · Database

Database Gaps

The schema is well-designed and the FR-AI-002 guarantee is genuinely a database-level constraint — the gaps are all in data, not structure.

Operational data gap — RESOLVED (Sep 21, 2026)

RESOLVED Sep 21, 2026: the audit found 0 rows in ExchangeRates and PlaceInterests; both were populated by the existing AI-track seeders (seed_exchange_rates.py → 3 rates, Seed_place_interests.py → 57 links) — no new data invented. Verified end-to-end: POST /api/destinations/suggestions now returns 200 with USD-converted totals (Amman 596 JOD → 840.36 USD). Remaining risk: seeding is still manual — GAP-001 tracks automation.

Documentation lags the schema

Docs/05 documents 17 tables. The shipped database has 20 — ExchangeRate, PlaceInterest, and UserPreferences were added without updating the spec.

Retention policy unimplemented

Docs/05 §16 specifies a 30-day retention window on AIGeneration.raw_output. No purge job or endpoint exists anywhere in the codebase — every raw AI response is retained indefinitely.

Fresh-clone reproducibility

Sharpened by PR #66: migration 20260921001200_RemoveBackendStaticSeed wipes the legacy static seed on fresh databases — a new DB now starts with zero reference rows (not even countries/currencies). Migrations auto-run only in Dev/Testing; the AI seeders are the only provisioning path.

What's solid

All 17-vs-20 documented entities are correctly normalized to 3NF with two explicitly justified denormalizations (cached trip total, snapshotted item cost). ItineraryItem.place_id is a genuine non-nullable foreign key — the anti-hallucination guarantee holds even if application-layer validation were bypassed. Delete behavior (RESTRICT / CASCADE / SET NULL) is deliberately chosen per relationship, not defaulted.

14 · DevOps

DevOps / Deployment Gaps

Biggest movement since the audit: a full CI/CD pipeline and a Render blueprint landed on main. The remaining risk is the last mile — proving a green run and a reachable staging URL.

CI/CD pipeline shipped — status needs a fresh check

ci-cd.yml runs the backend build + full xUnit suite against a SQL Server 2022 service container (with coverage), Flutter analyze + widget tests, and — only on a push to main after both pass — triggers the Render deploy hook. The 2026-09-19 QA log had reported red CI; the pipeline has since been merged, so verify the latest run before trusting main.

Hosting decision (D3) effectively made: Render

render.yaml defines a free-tier Docker web service with a /health check and auto-deploy off (deploys are test-gated via the CI hook). Azure SQL connection string, Gemini key, and the CORS origin are dashboard-set secrets; the JWT key is auto-generated. Still unproven: a deployed, publicly reachable staging URL.

Docker CSV path bug

ExtraAiContextReader's default relative path to Extra_AI_Context.csv does not exist inside the container's build context. Budget-first generation will fail in Docker with a file-not-found error unless the CSV is mounted — unverified in-container during this audit (only destination-first was exercised live).

Staging deploys won't auto-migrate the database

Program.cs runs db.Database.Migrate() only in Development/Testing — but render.yaml sets ASPNETCORE_ENVIRONMENT=Staging. The first Render deploy will boot against a database migrations have never touched. A migration step (release command or one-off job) must be added before go-live (GAP-022).

Explicitly out of current team capability (flagged, not silently skipped)

Penetration testing, secrets-management infrastructure, formal compliance review, centralized logging/monitoring (ELK/Application Insights/Grafana), and microservices/distributed-systems operations. All correctly scoped as external or future learning tracks in the project's own planning documents rather than assumed.

21 · Done

Definition of Done

What must be true before Triply can reasonably be called MVP-complete — combining the project's own stated definition with what this audit found still open.

Per the project's own Definition of Done (Master Plan §13)

A feature is done when it matches its SRS requirement and acceptance criteria, is covered by the owning track's demonstrated testing method, passes the agreed API/JSON contract, and has been reviewed via pull request.

Concrete, project-specific completion bar

1 · Reproducible from zero

A fresh clone plus docker compose up can generate a real itinerary without any manual database surgery.

2 · The non-negotiable rule is proven, not just enforced

0% invented places is demonstrated by an automated test at the HTTP layer, not only by application logic and a separate Python harness.

3 · Both planning modes fully work, live

Destination-first (already proven) and budget-first (seeded + live-verified Sep 21, 2026) both complete end-to-end against the live Gemini API and a properly seeded database.

4 · CI is green and trustworthy

The pipeline exists — now prove a green run on main and keep every change checked against it before being relied upon.

5 · Both platforms are real

Mobile parity is QA-verified against a live backend (not just self-reported), and Web parity (FR-WEB-001) exists at all.

6 · Every open decision is closed

D1–D5 (SRS), the AI contract's budget-check policy, the UI/UX visual-system conflict, and the cybersecurity ownership question all have an explicit answer on record.

7 · Deployed somewhere real

Hosting is decided (Render) and the blueprint is merged — what remains is the staging URL actually answering /health, with migrations applied.

8 · Documentation matches reality

Table counts, framework versions, and API examples in the docs reflect what's actually shipped.

22 · Summary

Final Project State

A one-page answer to: is Triply done, and if not, what's actually left.

Ready

Auth, trip lifecycle, destination-first planning, AI generation with genuine 0%-invented-place grounding (prompt + validation + DB-FK), cost aggregation, partial regeneration (code), 17 mobile screens wired to real endpoints, a gated CI/CD pipeline + Render blueprint, and a documentation set that flags its own open questions rather than hiding them.

Incomplete

Budget-first suggestions now work in the live environment (seeded + verified Sep 21, 2026), but provisioning remains manual — automated dataset provisioning is still open (fresh DBs start fully empty by design now). Also open: AI contract steps specified but not wired in (maxItems, budget check, schema provenance), thin negative-path test coverage for the central guarantee, and a Flutter Web build that hasn't started despite being a Must-have.

Unverified

Current CI status on main (pipeline merged after the last red report), the Render staging URL (secrets defined, reachability unproven), 4 mobile QA re-test items, live partial regeneration against real Gemini, in-Docker budget-first generation, and NFR-PERF-001's latency target (TBD).

Must happen next

In order: automate data seeding (P0) → prove CI green and close the grounding hole (P1) → harden AI tests and sign off the contract (P1) → resolve the design conflict and start Web (P1) → reachable staging + security hygiene (P2) → refresh documentation (P3).

The honest one-line verdict: Triply's hardest problem — building an LLM pipeline nobody on the team had used before, that provably never invents a place — is solved and working, and the pipeline to ship it now exists too. What remains is disciplined finishing work: seed the data, prove the runs, resolve the open decisions, and build the platform that was promised but not yet started.
